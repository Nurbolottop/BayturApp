# BAYTUR — онлайн-оплата через Freedom Pay (для мобильного приложения)

Документ для мобильной команды и её AI-ассистента: как во Flutter-приложении провести оплату денежной части
заявки через Freedom Pay. Дополняет [`MOBILE_API.md`](MOBILE_API.md), §8 «Заявки на кешбек» и §9 «Онлайн-оплата»;
общие правила (заголовки, токены, формат ошибок, WebSocket) — там же.

**Статус (06.10.2026):** Freedom Pay подключён на сервере и проверен боевыми платежами: банковская карта и MBank
(интернет-банкинг), автоматический возврат по карте. Finik и ЭлQR пока идут через тестовую страницу (§8 этого документа).

---

## 1. Как это устроено

Приложение **не работает с Freedom Pay напрямую**: нет SDK, ключей и подписи на клиенте. Сервер создаёт
платёж у Freedom Pay и отдаёт ссылку на его страницу оплаты. Клиент платит на этой странице (карта, MBank,
MegaPay, O!Деньги — что включено для магазина). Результат Freedom Pay присылает **серверу**, сервер сообщает
приложению.

```
Приложение                Сервер BAYTUR                  Freedom Pay
    │ POST /payments            │                              │
    │──────────────────────────▶│ init_payment ───────────────▶│
    │ ◀── 201 {redirectUrl} ────│                              │
    │                                                          │
    │ открыть redirectUrl ────────────────────────────────────▶│ клиент платит
    │                           │ ◀──── результат (подписан) ──│
    │ ◀── WS payment.updated ───│                              │
    │ ◀── baytur://payment/{id} ─────────── возврат со страницы│
    │ POST /cashback-requests   │                              │
    │──────────────────────────▶│                              │
```

Главное правило: **оплачено только то, что сервер вернул со `status: "paid"`**. Возврат по диплинку,
закрытие браузера, URL страницы — не признак оплаты.

## 2. Сценарий по шагам

### Шаг 1. Посчитать сумму

`POST /cashback-requests/quote` (MOBILE_API §8.2) → `moneySom` — сколько платить деньгами. Способ `freedomPay`
показывайте, только если он есть в `methods` ответа quote (или категории в каталоге). Если `moneySom = 0`
(всё баллами), оплата не нужна — сразу `POST /cashback-requests`.

### Шаг 2. Создать платёж

```http
POST /payments
Authorization: Bearer <accessToken>

{"method": "freedomPay", "amountSom": 3500, "itemId": "spa-stone",
 "quantity": 1, "checkAmount": null, "pointsSom": 0}
```

`amountSom` = `moneySom` из quote; `itemId`, `quantity`, `checkAmount`, `pointsSom` — те же, что в quote.

```json
// 201 Payment
{"id": "pay_fxanw7yapwkz11", "method": "freedomPay", "amount": 3500, "status": "created",
 "redirectUrl": "https://customer.freedompay.kg/pay.html?customer=01a1...&lang=ru",
 "qrPayload": null, "expiresAt": "2026-10-06T22:56:00+06:00", "paidAt": null, "requestId": null}
```

- Каждый вызов создаёт **новый** платёж. Блокируйте кнопку «Оплатить» на время запроса, чтобы не создать два.
- Сохраните `payment.id` локально (например, в состоянии экрана оплаты и в SharedPreferences) — он нужен,
  если приложение выгрузят, пока клиент платит (шаг 5).

Ошибки:

| HTTP | `error.code` | Что показать |
|---|---|---|
| 422 | `payment_invalid` | сумма устарела: взять `error.moneySom`, пересчитать экран и повторить |
| 422 | `method_not_allowed` | Freedom Pay недоступен для этой услуги — предложить другой способ |
| 422 | `insufficient_points`, `points_limit_exceeded`, `amount_out_of_range` | как на экране quote |
| 404 | `item_not_found` | «Услуга недоступна», вернуться в каталог |
| 403 | `account_frozen`, `account_blocked` | общий обработчик (MOBILE_API §3) |
| 503 | `payment_unavailable` | «Оплата сейчас недоступна, попробуйте позже». Платёж не создан, деньги не списаны |

### Шаг 3. Открыть страницу оплаты

Открывайте `redirectUrl` **во встроенном системном браузере**, не во `WebView`:

```dart
await launchUrl(Uri.parse(payment.redirectUrl!), mode: LaunchMode.inAppBrowserView);
// iOS — SFSafariViewController, Android — Chrome Custom Tabs
```

Почему не `WebView`: на странице Freedom Pay клиента перебрасывает в приложение банка (MBank и др.) и на
3-D Secure. В `WebView` переходы в приложения банков и `baytur://` не работают без ручной обработки, а
Custom Tabs / SFSafariViewController делают это сами.

Шаг мобилки на экране оплаты: `redirecting` → после открытия браузера `processing`.

### Шаг 4. Вернуться в приложение

После оплаты (или отказа) Freedom Pay открывает страницу сервера
`https://app.baytur.kg/api/v1/payments/{id}/return`. Она:

- на телефоне сразу переходит по диплинку **`baytur://payment/{id}`** — приложение должно его открыть;
- показывает логотип, сумму и итог («Оплата прошла» / «Проверяем оплату…» / «Оплата не прошла» /
  «Оплата возвращена») и кнопку «Вернуться в приложение» — на случай, если диплинк не сработал.

Что сделать в приложении:

1. **Зарегистрировать схему `baytur`** (если ещё нет):
   - iOS, `Info.plist`: `CFBundleURLTypes` → `CFBundleURLSchemes` = `baytur`;
   - Android, `AndroidManifest.xml`, в `<activity>` приложения:
     ```xml
     <intent-filter>
       <action android:name="android.intent.action.VIEW"/>
       <category android:name="android.intent.category.DEFAULT"/>
       <category android:name="android.intent.category.BROWSABLE"/>
       <data android:scheme="baytur" android:host="payment"/>
     </intent-filter>
     ```
2. **Обработать `baytur://payment/{id}`** (например, пакетом `app_links`): закрыть браузер
   (`closeInAppWebView()` — на iOS SFSafariViewController сам не закроется), открыть экран оплаты этого
   платежа и перейти к шагу 5.
3. **Не полагаться только на диплинк.** Клиент может закрыть браузер крестиком или вернуться в приложение
   вручную. Поэтому при возврате приложения на передний план (`AppLifecycleState.resumed`), если есть
   незавершённый платёж, — тоже шаг 5.

### Шаг 5. Дождаться результата

Источник правды — статус платежа на сервере:

- **WebSocket** `payment.updated` (MOBILE_API §10.1), `data` = `Payment`;
- и/или **опрос** `GET /payments/{id}` каждые 2–3 с, пока статус `created` / `pending`;
- при возврате в приложение один раз вызвать **`POST /payments/{id}/check`** — сервер сам спросит статус
  у Freedom Pay (полезно, если уведомление от Freedom Pay ещё в пути). Ответ — тот же `Payment`.

| `status` | Что значит | Что делать |
|---|---|---|
| `created`, `pending` | клиент ещё платит / результат в пути | крутить «Проверяем оплату…»; опрашивать до `expiresAt` |
| `paid` | деньги получены | шаг 6 |
| `failed` | отказ банка / клиент отменил / сумма не совпала | «Оплата не прошла», деньги не списаны; можно создать **новый** платёж (шаг 2) |
| `expired` | клиент не оплатил за 30 минут | «Время на оплату истекло», новый платёж |
| `refunded` | сервер вернул деньги (см. §4) | «Оплата возвращена» |

Если результата нет дольше ~1 минуты после возврата в приложение — не блокируйте экран: покажите
«Проверяем оплату, это может занять пару минут» и дайте уйти. Сервер доведёт заявку сам (§4).

### Шаг 6. Отправить заявку

```http
POST /cashback-requests
Idempotency-Key: <uuid, один на этот платёж>

{"itemId": "spa-stone", "quantity": 1, "pointsSom": 0, "method": "freedomPay", "paymentId": "pay_fxanw7yapwkz11"}
```

Параметры — **те же, что при создании платежа**. Дальше — обычная заявка (MOBILE_API §8).

- `422 payment_invalid` — платёж не оплачен, уже привязан к другой заявке или параметры не совпали.
  Если `payment.requestId` уже не `null` — заявку создал сервер (§4), просто откройте её.

## 3. Срок жизни платежа

- Страница Freedom Pay принимает оплату **30 минут** с момента создания.
- `expiresAt` — на 5 минут позже (запас на запаздывающее уведомление). После него сервер переводит
  неоплаченный платёж в `expired`.
- Для «Точки приёма платежей» (терминалы) это значит: оплатить нужно в течение 30 минут.

---

## 4. Что сервер делает сам

- **Заявка без приложения.** Если платёж `paid`, а заявку за ~10 минут не прислали (приложение закрыли,
  пропал интернет), сервер создаёт её сам по параметрам платежа — `payment.requestId` станет не `null`,
  придёт `request.updated`.
- **Автовозврат.** Если создать заявку уже нельзя (не хватает баллов, услугу скрыли), а также при отказе
  или отмене заявки и при уменьшении суммы сотрудником — сервер возвращает деньги через Freedom Pay
  (полностью или частично). Платёж получает `status: "refunded"` (при полном возврате) → `payment.updated`.
- **Деньги после истечения.** Если оплата пришла, когда платёж у нас уже `expired` (или сумма не совпала),
  сервер отклоняет её у Freedom Pay и деньги возвращаются клиенту — если Freedom Pay позволяет отказ для этого
  способа оплаты; иначе курорт возвращает деньги вручную.

Автовозврат проверен для банковских карт. Для MBank, MegaPay, O!Деньги и терминалов поддержку возврата
уточняем у Freedom Pay — если возврат не пройдёт, курорт вернёт деньги вручную.

## 5. Страница оплаты Freedom Pay — что увидит клиент

- Название магазина, описание услуги («BAYTUR: Делюкс, вид на озеро»), сумма в сомах (KGS).
- Способы: «Банковская карта», «Интернет-банкинг» (сейчас MBank), «Электронные кошельки» (MegaPay, O!Деньги),
  «Точка приёма платежей». Набор включает Freedom Pay — **в приложении его не повторяйте**: одна кнопка
  «Freedom Pay», выбор способа — на их странице.
- Ограничение MegaPay: от 5 до 15 000 сом за платёж (для дорогих услуг — карта или банк).
- Язык страницы — русский.

## 6. Тестирование

| Режим сервера | Что происходит |
|---|---|
| **Тестовый** (сейчас) | Страница Freedom Pay принимает только **тестовые карты** (выдаёт менеджер Freedom Pay). Настоящая карта → ошибка 1210 «Неправильный/несуществующий номер тестовой карты» → платёж `failed`. Деньги не списываются |
| **Боевой** | Настоящие деньги. Включается на сервере перед запуском |

Что проверить в приложении в тестовом режиме, даже без тестовой карты:

1. Создание платежа и открытие страницы Freedom Pay в Custom Tabs / SFSafariViewController.
2. Ввод настоящей карты → ошибка 1210 → «Вернуться к покупкам» → возврат по `baytur://payment/{id}` →
   статус `failed` → экран «Оплата не прошла» → новый платёж создаётся.
3. Закрытие браузера крестиком → `resumed` → `/check` → корректный статус.
4. Выгрузка приложения во время оплаты → при запуске находится незавершённый платёж.
5. `503 payment_unavailable` и `422 payment_invalid` — тексты ошибок.

Успешную оплату проверяем тестовой картой от Freedom Pay или в боевом режиме небольшой суммой — по
договорённости с владельцем, сервер в этом случае сам вернёт деньги (§4).

## 7. Чек-лист для мобилки

- [ ] Кнопка Freedom Pay → `POST /payments` с `method: "freedomPay"`, блокировка двойного нажатия.
- [ ] `redirectUrl` открывается в `LaunchMode.inAppBrowserView`, не в WebView.
- [ ] Схема `baytur` зарегистрирована на iOS и Android; `baytur://payment/{id}` закрывает браузер и ведёт на экран оплаты.
- [ ] На `resumed` с незавершённым платежом — `POST /payments/{id}/check`.
- [ ] Ожидание результата: `payment.updated` + опрос `GET /payments/{id}` каждые 2–3 с до `expiresAt`.
- [ ] Оплатой считается только `status: "paid"` с сервера.
- [ ] После `paid` — `POST /cashback-requests` с `paymentId` и `Idempotency-Key`; если `requestId` уже есть — открыть заявку.
- [ ] Экраны/тексты для `failed`, `expired`, `refunded`, `503 payment_unavailable`, `422 payment_invalid`.
- [ ] `payment.id` незавершённого платежа переживает перезапуск приложения.
- [ ] Удалён демо-код оплаты (`FakePaymentGateway`, имитация «Оплатить / Отказ»).

---

## 8. Finik и ЭлQR

Пока не подключены: для них `POST /payments` возвращает тестовую страницу «Оплатить / Отказ» (Finik) или
тестовый `qrPayload` (ЭлQR), деньги не списываются. Контракт API тот же — когда провайдеры подключат,
в приложении менять ничего не придётся.
