## 0. Инструкция для AI-ассистента

Ты дорабатываешь Flutter-приложение BAYTUR под новую балловую систему. Правила работы:

1. **Приложение ничего не считает.** Уровень, прогресс, остаток до уровня, удержание, «в зоне риска», пол —
   всё приходит из `GET /wallet`. Удали `TierProgram.statusFor(lifetime)` и любой локальный расчёт уровня.
   Единственное место, где правила из §2 реализуются в коде приложения, — демо-сервер (§8).
2. **Уровни не фиксированы.** `TierId` — строка, а не enum. Уровни приходят из `GET /loyalty/program` в порядке
   `order`; их может быть больше или меньше шести. Шесть известных id (`bronze`, `silver`, `gold`, `platinum`,
   `titanium`, `ambassador`) — только константы для локальных медалей; для любого другого id стиль берётся
   из `style` сервера. Неизвестный id **не должен ронять** приложение.
3. **Неизвестные значения enum не роняют парсинг** (`kind` операций, `reason`, `result`, `cause`, `type` событий) —
   пропускай или показывай нейтральный вариант.
4. **«За всё время» (`lifetime`) не показывается на главных экранах** — только в Профиль → Настройки →
   «Баллы за всё время». На карте баланса и в оплате — `available`, на картах уровней — `current`.
5. **Не трогай** стиль, токены и анимации — используй существующие (`SpinningMedal`, `showCelebration`,
   `AnimatedNumber`, `TierProgressBar`, `PopIn`). Всё уважает «Уменьшить движение» и экономную графику.
6. **Все новые тексты — в три .arb** (ru, ky, en), ключи из §9.
7. **Порядок работ:** модели и парсинг (§3, §7) → демо-сервер с правилами и тестами (§8) → карта баланса →
   вкладка «Уровни» → профиль и лист «Баллы за всё время» → push и реакции (§4, §6) → тесты (§10).
8. Каждый шаг заканчивай зелёными тестами. Если формат ответа в этом документе расходится с ответом сервера —
   прав сервер (машинная схема: `https://app.baytur.kg/api/v1/schema`), сообщи о расхождении.

## 1. Суть изменений за 2 минуты

Раньше: один баланс, уровень — по сумме всех заработанных баллов (`lifetime`), уровень не падал, баллы сгорали.

Теперь у клиента **три счётчика**:

| Счётчик | Поле API | Растёт | Уменьшается | Где показываем |
|---|---|---|---|---|
| **Доступные** | `available` | при начислении кешбека | при оплате баллами | крупно на карте баланса, оплата баллами |
| **Нынешние** | `current` | при начислении кешбека | **обнуляются** при повышении уровня и 1 января; траты их **не** уменьшают | карточки уровней, подпись к прогрессу |
| **За всё время** | `lifetime` | при начислении кешбека | никогда (кроме отмены ошибочного начисления) | только Профиль → Настройки |

- **Уровень решают «Нынешние».** Порог уровня (`threshold`) — сколько «Нынешних» нужно собрать **на предыдущем
  уровне за один календарный год** (а не нарастающий итог).
- **Каждый год уровень надо подтверждать.** 1 января сервер закрывает год: если уровень получен раньше этого года
  и клиент не собрал **лимит**, уровень понижается на одну ступень. Лимит = собранное за год на уровне + 10 000.
- **Пол (вечный уровень).** Уровень на одну ступень ниже наивысшего достигнутого — вечный: ниже него клиент не упадёт.
  Достиг Золота → Серебро навсегда; достиг Платины → Золото навсегда.
- **Титан и Амбассадор** требуют ещё и **заданий** (ачивок): «Быть клиентом 5 лет подряд» и т. п.
- **Баллы больше не сгорают.** `expiresAt`, `points.expiring`, `points.expired` удалены.
- **Уровни:** Бронза → Серебро → Золото → Платина → **Титан** (раньше `diamond`) → **Амбассадор** (новый).

Курс прежний: 100 баллов = 1 сом. Резерв под заявки работает как раньше.

## 2. Правила (для текстов и демо-сервера)

Пороги для примеров: Серебро 200 000, Золото 300 000, Платина 900 000, надбавка к лимиту 10 000.

### 2.1. Начисление
Кешбек `P` добавляется во все три счётчика: `lifetime += P`, `current += P`, `available += P`. Сразу после —
проверка повышения.

### 2.2. Трата
Только из «Доступных»: при заявке — в резерв, при подтверждении — `available −= P`, при отказе/отмене резерв
возвращается. `current` и `lifetime` не меняются. Потратить можно не больше `available` (резерв уже вычтен).

### 2.3. Повышение
```
next = следующий уровень после текущего
пока next есть И current >= next.threshold И выполнены задания next «для получения»:
    tier = next; tierSince = сейчас; maxReached = max(maxReached, next)
    current = 0                       // излишек сверх порога для «Нынешних» сгорает
    событие tier.upgraded
```
Если баллов хватает, а заданий нет — «Нынешние» продолжают расти; повышение произойдёт в момент выполнения
последнего задания.

### 2.4. Закрытие года (1 января 00:00, Бишкек)
```
T = уровень, F = пол
проверки нет, если: T базовый (Бронза) → not_required
                    T == F (вечный)     → floor
                    T без подтверждения → not_required
                    T получен в этом году → promoted_in_period
иначе: ok = current >= limit[T] (и выполнены задания «для подтверждения», если они есть)
       ok  → retained (событие tier.retained)
       нет → tier = max(на один ниже, F) → dropped (событие tier.downgraded)
лимит (если остался на T и T не вечный): limit[T] = max(limit[T], current + 10 000)
current = 0, начинается новый год
```
Лимит хранится по каждому уровню и не теряется при понижении: вернулся на Золото — прежний лимит Золота.

### 2.5. Пол
```
floor = уровень на floorDepth (по умолчанию 1) ступеней ниже maxReached (наивысшего достигнутого)
пока у floor canBeFloor = false и floor не базовый: floor = на ступень ниже
```

| Наивысший достигнутый | Пол |
|---|---|
| Серебро | Бронза |
| Золото | Серебро |
| Платина | Золото |
| Титан | Платина |
| Амбассадор | Платина (Титан полом быть не может) |

За Титан и Амбассадор нужно бороться каждый год, но дошедший до Титана ниже Платины уже не упадёт.
Пример: Амбассадор не подтвердил → Титан, не подтвердил → Платина, дальше Платина навсегда.

### 2.6. Сквозной пример (обязателен для тестов демо-сервера)

| Момент | Событие | За всё время | Нынешние | Доступные | Уровень | Лимит Золота |
|---|---|---|---|---|---|---|
| март 2026 | +200 000 → Серебро | 200 000 | 0 | 200 000 | Серебро | — |
| июнь 2026 | потратил 100 000 | 200 000 | 0 | 100 000 | Серебро | — |
| август 2026 | +300 000 → Золото | 500 000 | 0 | 400 000 | Золото | — |
| декабрь 2026 | +500 000 | 1 000 000 | 500 000 | 900 000 | Золото | — |
| 1 янв 2027 | получено в 2026 — без проверки; лимит 510 000 | 1 000 000 | 0 | 900 000 | Золото | 510 000 |
| декабрь 2027 | +400 000 | 1 400 000 | 400 000 | 1 300 000 | Золото | 510 000 |
| 1 янв 2028 | 400 000 < 510 000 → Серебро (навсегда) | 1 400 000 | 0 | 1 300 000 | Серебро | 510 000 |
| май 2028 | +300 000 → снова Золото | 1 700 000 | 0 | 1 600 000 | Золото | 510 000 |
| декабрь 2028 | +800 000 | 2 500 000 | 800 000 | 2 400 000 | Золото | 510 000 |
| 1 янв 2029 | получено в 2028 — без проверки; 810 000 > 510 000 | 2 500 000 | 0 | 2 400 000 | Золото | 810 000 |

## 3. API: что изменилось

Все ответы — JSON camelCase, баллы — целые числа, даты — ISO 8601 **в поясе курорта** (`+06:00`),
тексты — на языке `Accept-Language`.

### 3.1. `GET /wallet` — единственный источник цифр для главной и уровней

```json
{
  "available": 1300000,
  "reserved": 0,
  "current": 400000,
  "lifetime": 1400000,
  "pendingCashback": 0,

  "tier": {
    "id": "gold",
    "since": "2026-08-12T16:00:00+06:00",
    "floor": "silver",
    "isFloor": false,
    "maxReached": "gold",
    "next": {
      "id": "platinum",
      "threshold": 900000,
      "left": 500000,
      "progress": 0.4444,
      "achievements": {"required": 0, "done": 0}
    },
    "retention": {
      "required": true,
      "reason": "check",
      "periodEnd": "2027-12-31T23:59:59+06:00",
      "limit": 510000,
      "collected": 400000,
      "left": 110000,
      "progress": 0.7843,
      "atRisk": true,
      "dropTo": "silver",
      "achievements": {"required": 0, "done": 0}
    }
  },

  "period": {"key": "2027", "start": "2027-01-01T00:00:00+06:00", "end": "2027-12-31T23:59:59+06:00"},

  "balance": 1300000,
  "nextTier": "platinum",
  "leftToNext": 500000,
  "progress": 0.4444
}
```

| Поле | Правило |
|---|---|
| `available` | можно потратить прямо сейчас, резерв уже вычтен — крупное число на карте баланса |
| `tier.floor` / `tier.isFloor` | вечный уровень клиента; `isFloor = true` — показать замок «Навсегда ваш» |
| `tier.maxReached` | наивысший достигнутый; если выше текущего — на карте того уровня «Вы уже были на этом уровне» |
| `tier.next` | `null` на высшем уровне. `progress = min(1, current / threshold)`. `achievements.required` — сколько заданий нужно для входа, `done` — сколько выполнено |
| `tier.retention.reason` | `check` — в конце года проверка; `floor` — уровень вечный; `new_this_period` — получен в этом году, проверки не будет; `not_required` — уровень без подтверждения (Бронза) |
| `tier.retention.*` | при `reason ≠ check` есть только `required`, `reason`, `periodEnd`; остальные поля — только при `check` |
| `tier.retention.atRisk` | `true`, если до конца года меньше 60 дней и лимит (или задания подтверждения) не выполнены |
| `tier.retention.dropTo` | куда упадёт уровень, если не подтвердить («иначе — Серебро») |
| `period` | текущий год; `end` — включительно |
| `balance`, `nextTier`, `leftToNext`, `progress` | **устарели**, только для старых версий; новая версия их не читает |
| `expiresAt` | **удалён** |

### 3.2. `GET /loyalty/program` (публичный, с ETag)

```json
{
  "tiers": [
    {
      "id": "bronze", "order": 0, "name": "Бронза", "threshold": 0,
      "canBeFloor": true, "retention": "none",
      "entryRule": {"mode": "all", "n": null},
      "style": {"gradient": ["#4A220F", "#99562C", "#D9976A"], "glow": "#D9976A", "medalUrl": null, "icon": null},
      "achievements": [],
      "from": 0, "colors": ["#4A220F", "#99562C", "#D9976A"], "medal": null
    },
    {
      "id": "titanium", "order": 4, "name": "Титан", "threshold": 2000000,
      "canBeFloor": false, "retention": "points_and_achievements",
      "entryRule": {"mode": "all", "n": null},
      "style": {"gradient": ["#140F3A", "#4B3DB0", "#8FD8FF"], "glow": "#8FD8FF", "medalUrl": null, "icon": null},
      "achievements": [{"id": "five-years", "usage": "entry"}, {"id": "annual-evening", "usage": "retention"}],
      "from": 3400000, "colors": ["#140F3A", "#4B3DB0", "#8FD8FF"], "medal": null
    }
  ],
  "privileges": [
    {"id": "cashback", "tier": "bronze", "icon": "cashback", "title": "Кешбек баллами", "short": "Кешбек",
     "description": "Баллы за каждую оплату деньгами: 100 баллов = 1 сом."}
  ],
  "achievements": [
    {"id": "five-years", "title": "Быть клиентом 5 лет подряд", "description": "Хотя бы одна покупка в каждом году",
     "icon": "calendar", "scope": "lifetime"}
  ],
  "settings": {"periodType": "calendar_year", "floorDepth": 1}
}
```

- `tiers` — отсортированы по `order` снизу вверх; только активные уровни.
- `threshold` — в UI «Соберите N за год». У базового 0.
- `retention`: `none` · `points` · `points_and_achievements`.
- `entryRule.mode`: `all` — все задания «для получения»; `any_n` — любые `n` из привязанных.
- `achievements[].usage` у уровня: `entry` (для получения), `retention` (для подтверждения), `both`.
  Тексты и иконки заданий — в `achievements` верхнего уровня (только видимые клиенту).
- `style.gradient` — 3 цвета от тёмного к светлому (`LinearGradient` 135°, остановки 0 / 0.55 / 1);
  `glow` — свечение; `medalUrl` — PNG/WebP медали или `null` (рисовать стандартную медаль в цветах градиента).
- `from`, `colors`, `medal` — **устарели** (для старых версий); новая версия читает `threshold` и `style`.

### 3.3. `GET /me/achievements` — новый (нужен вход)

```json
{"items": [
  {"id": "five-years", "progress": 3, "target": 5, "completedAt": null, "periodKey": null},
  {"id": "annual-evening", "progress": 1, "target": 1, "completedAt": "2027-06-10T19:00:00+06:00", "periodKey": "2027"}
]}
```

Прогресс по видимым заданиям. `periodKey` — для заданий «за год» (обнуляются 1 января), `null` — «за всё время»
(раз выполненное остаётся выполненным). `progress` не больше `target`.

### 3.4. `GET /me/loyalty/history` — новый (нужен вход)

```json
{
  "lifetime": 2500000,
  "memberSince": "2026-03-01",
  "periods": [
    {"key": "2028", "tierStart": "silver", "tierEnd": "gold", "collected": 800000, "limit": 510000, "result": "promoted_in_period"},
    {"key": "2027", "tierStart": "gold", "tierEnd": "silver", "collected": 400000, "limit": 510000, "result": "dropped"},
    {"key": "2026", "tierStart": "gold", "tierEnd": "gold", "collected": 500000, "limit": null, "result": "promoted_in_period"}
  ],
  "tierChanges": [
    {"from": "silver", "to": "gold", "at": "2028-05-01T12:00:00+06:00", "cause": "promotion"},
    {"from": "gold", "to": "silver", "at": "2028-01-01T00:00:00+06:00", "cause": "period_drop"}
  ]
}
```

Списки — новые сверху. `result` → плашка: `retained` «Подтверждён», `promoted_in_period` «Новый», `dropped` «Понижен»,
`floor` «Навсегда», `not_required` — без плашки. `cause`: `promotion`, `period_drop`, `admin`, `migration`.
`limit` — лимит, с которым сравнивали (может быть `null`).

### 3.5. `GET /me/summary` — изменён

```json
{"available": 1300000, "current": 400000, "lifetime": 1400000, "requestsCount": 12}
```
Профиль показывает «Доступно · Нынешние · Заявок». `lifetime` остаётся в ответе, но на экране не показывается.

### 3.6. `GET /wallet/operations` — изменён

Только движения «Доступных» (`points` = изменение «Доступных», со знаком). Служебные записи (резерв, обнуление
«Нынешних») не приходят.

| `kind` | Показ |
|---|---|
| `cashback` | начисление за услугу |
| `spend` | оплата баллами |
| `refund` | возврат |
| `reversal` | **новый**: «Отмена начисления · {услуга}» |
| `adjustment` | ручная корректировка курорта (±), показывать `reason` |
| `forfeit` | списание при удалении аккаунта |
| `expire` | только старые записи (новых не будет) |

### 3.7. Ошибки
`insufficient_points` — как раньше (потратить можно не больше `available`). Других новых ошибок у мобильного API нет.

## 4. События и push

**WebSocket `/events`** — формат прежний `{"type": "...", "data": {...}}`.

| type | data | Что делает приложение |
|---|---|---|
| `wallet.updated` | объект `GET /wallet` | обновить карту баланса и уровни (любое изменение счётчиков или уровня) |
| `tier.upgraded` | `{type, tierId, fromTierId?}` | праздничный экран (§6) |
| `tier.downgraded` | `{type, tierId, fromTierId}` | лист понижения при следующем открытии |
| `tier.retained` | `{type, tierId}` | тост с медалью |
| `achievement.completed` | `{type, achievementId, tierId?}` | тост с иконкой задания, галочка в чек-листе |

**Push (FCM)** — `data.type` для перехода (все значения в `data` — строки):

| `data.type` | Доп. поля | Куда ведёт | Когда / настройка |
|---|---|---|---|
| `tier.upgraded` | `tierId`, `fromTierId?` (и устаревшее `tier`) | вкладка «Уровни» → уровень `tierId` | повышение; «Начисление кешбека» |
| `tier.downgraded` | `tierId`, `fromTierId` | вкладка «Уровни» → `tierId` | понижение 1 января; всегда |
| `tier.retained` | `tierId` | вкладка «Уровни» → `tierId` | уровень подтверждён; «Начисление кешбека» |
| `tier.at_risk` | `tierId`, `dropTo?` | вкладка «Уровни» → `tierId` | за 60, 30 и 7 дней до конца года; «Акции и события»; **только push, в ленту не пишется** |
| `achievement.completed` | `achievementId`, `tierId?` | вкладка «Уровни» → уровень с заданием | задание выполнено; «Начисление кешбека» |
| `points.adjusted` | — | «История» | как раньше |
| ~~`points.expiring`~~, ~~`points.expired`~~ | — | **удалены** | — |

## 6. Реакции и анимации

- **Повышение** (`tier.upgraded` или смена `tier.id` вверх при перечитывании кошелька): праздничный экран —
  медаль нового уровня влетает и крутится (`SpinningMedal`), салют по краям (`showCelebration`), звук success,
  кнопка «Смотреть привилегии». **Один раз на повышение** — отметка в SharedPreferences по `tier.since`.
- **Понижение**: спокойный лист при первом открытии после смены года, без салюта и звука:
  «В 2027 году вы собрали 400 000 из 510 000. Ваш уровень — Серебро, он останется с вами навсегда. Чтобы вернуть
  Золото, соберите 300 000». Данные: последний элемент `periods` из `/me/loyalty/history` (`collected`, `limit`),
  «навсегда» — если `tier.isFloor`, «соберите» — `tier.next.threshold`. Показ один раз на `period.key`.
- **Подтверждение уровня / уровень стал вечным**: тост с медалью.
- **Задание выполнено**: тост с иконкой задания; в чек-листе галочка с «пружиной» (`PopIn`).
- Бары и числа пересчитываются плавно (`AnimatedNumber`, `TierProgressBar`). При обнулении «Нынешних» бар сначала
  доходит до конца, затем стартует с нуля уже на новом уровне.
- Всё уважает «Уменьшить движение» и экономную графику.

## 8. Демо-сервер

`fake_loyalty_server.dart` должен вести себя как бэкенд, чтобы все экраны проверялись без сервера.

**Состояние клиента:** `available` (вместе с резервом), `reserved`, `current`, `lifetime`, `tierId`, `tierSince`,
`maxReachedId`, `limits: Map<tierId, int>`, выполненные задания, история периодов и смен уровня, текущий год.

**Операции:** начисление (§2.1 + повышение §2.3), трата (§2.2), закрытие года (§2.4), выполнение задания
(отметить + повышение). Ответы — строго в формате §3.

**Демо-пульт:** «Начислить N», «Потратить N», **«Закрыть год»** (запускает §2.4 и сдвигает год),
**«Выполнить задание»** (выбор из заданий), «Сбросить». Пресеты состояний, чтобы быстро увидеть каждый
`retention.reason`, `atRisk`, вечный уровень, Титан с незакрытыми заданиями.

**Демо-данные программы:** 6 уровней с порогами 0 / 200 000 / 300 000 / 900 000 / 2 000 000 / 3 000 000;
Титан и Амбассадор: `canBeFloor: false`, `retention: points_and_achievements`, у каждого по одному заданию
«для получения» и одному «для подтверждения».

## 12. Изменения 08.10.2026 (ТЗ курорта)

**Курс и кешбек.** 1 балл = 1 сом (`settings.pointsPerSom = 1`). Кешбек единый для всех услуг:

```
Баллы = Сумма (деньгами) × 5 % × (1 + надбавка уровня / 100)
```

Надбавки по умолчанию (меняются в админке): Бронза 0 %, Серебро 10 %, Золото 25 %, Платина 50 %, Титан 75 %,
Амбассадор 100 %. За 100 000 сом: 5 000 / 5 500 / 6 250 / 7 500 / 8 750 / 10 000 баллов. Акция услуги или
день рождения повышают базовую ставку (берётся большая), надбавка уровня применяется поверх. В `quote` и заявке в
`bonuses` добавлен вид `{"kind": "tier", "tierId": "gold", "percent": 25}`. Балансы клиентов не пересчитывались.

**`GET /loyalty/program` — новые поля уровня:** `cashbackBonus` (%), `cashbackRate` (доля, 0.0625),
`permanent: {lifetime, years}` или `null`. `canBeFloor` = есть постоянный статус. В `settings` —
`baseCashbackRate` (0.05) и `pointsPerSom` (1). `floorDepth` устарел.

**Постоянный статус (навсегда)** — вместо прежнего «пол = ступень ниже наивысшего»: уровень присваивается навсегда,
когда одновременно баллов за всё время ≥ X и лет в программе ≥ Y:

| Уровень | Баллов за всё время | Лет в программе |
|---|---|---|
| Серебро | 50 000 | 1 |
| Золото | 100 000 | 2 |
| Платина | 175 000 | 3 |
| Титан | 200 000 | 4 |
| Амбассадор | 250 000 | 5 |

Он сразу поднимает уровень (без сброса «Нынешних»), и ниже него уровень не опускается. В `/wallet`
`tier.floor` / `tier.isFloor` / `retention.reason = floor` считаются по этому правилу. В истории уровней новая
причина `cause: "permanent"`. Временный статус (годовые пороги, подтверждение) — без изменений.

**Привилегии — «Апгрейдер», 21 шт.** Новые поля: `group` и `footnote` (мелким шрифтом, может быть `null`).
Одна `group` на разных уровнях — это одна привилегия, которая улучшается:

| group | Бронза | Серебро | Золото | Платина | Титан | Амбассадор |
|---|---|---|---|---|---|---|
| `points-rate` | 5 % | 5,5 % | 6,25 % | 7,5 % | 8,75 % | 10 % |
| `late-checkout` | — | до 13:00 | до 14:00 | до 16:00 | до 16:00 | до 18:00 |
| `room-upgrade` | — | — | +1 категория | +2 категории | +3 категории | до Президентского люкса |
| `bai-club` | — | — | — | ✓ | ✓ | ✓ |
| `welcome-gift` | — | — | — | ✓ | ✓ | ✓ |

У `late-checkout` сноска «Не гарантированно, предоставляется при наличии возможности». Тексты и числа приходят
готовыми (процент в `points-rate` подставлен сервером), всё правится в админке. Экран: показывайте группы строками,
по уровням — значение текущего уровня и следующее улучшение.
